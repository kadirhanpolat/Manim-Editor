# Phase 2.6 — Effects: Drop Shadow + Round Corners Design

**Date:** 2026-06-05
**Status:** Approved, ready for implementation planning
**Scope:** 2 new optional object effects — `shadow` (drop shadow) and round-corners
extension of the existing `cornerRadius` to polygon/triangle/star — in a single spec.
**Base branch:** `feat/phase2.6-effects`, branched from `main`.

## Goal

Extend the Phase 1 "Effects" system (CLAUDE.md "2D Object Effects (Phase 1)") with the
two render-faithful effects deferred to Phase 2: a configurable **drop shadow** and
**rounded corners for polygon/triangle/star** (via Manim's native `round_corners`).
Glow was evaluated and **dropped** — Manim CE has no true blur/glow, so a render would
only stack scaled low-opacity copies (concentric rings, not a soft glow); the fidelity
gap is not worth shipping.

Both effects follow the established conventions: optional object fields (absent ⇒
byte-identical legacy output), `applyEffects` Konva preview, the "Effects" section in
`PropertiesPanel.vue`, and `codegen.js` ↔ `manim.js` byte-identical helpers guarded by
`manim-export.test.js`.

## Non-Goals

- **Glow** — dropped (no faithful Manim render). May revisit as an honest "halo" later.
- Blur on the shadow in the render — Manim has no blur; `shadow.blur` is **preview-only**.
- Keyframing the effect fields. Standard keyframeable props are unaffected.
- Per-corner radius control — `cornerRadius` is a single uniform radius (as today).

## A) Drop Shadow

### Data Model
A single optional field, absent until enabled:
```js
obj.shadow = { color: '#000000', opacity: 0.4, dx: 8, dy: 8, blur: 12 }
```
- `dx`/`dy` — offset in **project px** (converted to Manim units for the render shift).
- `blur` — **preview-only** soft-edge radius (Manim cannot blur).
- `color`/`opacity` — the shadow copy's color and opacity.

### Eligibility
`SHADOW_TYPES` — a broad set of visual shapes:
`rectangle, square, circle, ellipse, triangle, star, polygon, heart, annulus, sector,
polygon_free, text, latex`. (Defined identically in codegen.js, manim.js, StageCanvas.vue,
PropertiesPanel.vue.)

### Codegen
A new helper `shadowLines(n, obj)` (byte-identical in both generators), appended in the
same post-construction effect-application spot as `gradientLine`/`dashedLines`, returns
`[]` when no shadow, else (each line single-line for round-trip):
```
_shadow_<n> = <n>.copy().set_color(<color>).set_opacity(<opacity>).shift([<dxm>, <dym>, 0])
<n> = VGroup(_shadow_<n>, <n>)
```
- `<dxm> = dx / sw * FRAME_WIDTH`, `<dym> = -dy / sh * FRAME_HEIGHT` (screen-down → Manim −y),
  each `.toFixed(3)`.
- `<color>` is the quoted hex; `<opacity>` is the numeric shadow opacity.
- The shadow copy is placed **first** in the VGroup (behind the styled shape).
- Ordering vs other effects: shadow wraps **last** (after gradient/dashed/round have
  styled `<n>`), so the shadow copies the fully-styled shape. `round_corners` (below)
  runs before shadow on the base `<n>`.

### Preview
`applyEffects` (StageCanvas.vue) sets Konva's native shadow props on the node when
`obj.shadow` is present and the type is in `SHADOW_TYPES`:
`shadowColor`, `shadowOpacity`, `shadowBlur` (= `blur * vs`), `shadowOffset = { x: dx*vs, y: dy*vs }`.
This yields a real soft shadow in preview.

### Round-Trip
The manim.js parser reconstructs `obj.shadow` from the `_shadow_<n> = <n>.copy()...shift([dxm, dym, 0])`
line (color, opacity, dx/dy via inverse conversion) and the following
`<n> = VGroup(_shadow_<n>, <n>)` line. `blur` is not emitted; it restores to a default
(`12`) on import.

## B) Round Corners (polygon / triangle / star)

### Data Model
**Reuse the existing `cornerRadius` field** (project px) — no new field. Today it drives
`RoundedRectangle` for rect/square; this adds polygon/triangle/star via Manim's native
`VMobject.round_corners`.

### Eligibility
Extend `ROUND_TYPES` (and the inspector's `canRound`) to add `polygon`, `triangle`,
`star`. Rect/square keep their existing `RoundedRectangle` path unchanged.

### Codegen
For `polygon`/`triangle`/`star` with `cornerRadius > 0`, after the shape is constructed
(and before shadow wrapping), emit a single line:
```
<n>.round_corners(radius=<cr_manim>)
```
- `<cr_manim> = cornerRadius / sw * FRAME_WIDTH` (radius scale), `.toFixed(3)`.
- Emitted by a byte-identical helper `roundCornersLine(n, obj)` returning `null` when not
  applicable (keeps rect/square and zero-radius output byte-identical to legacy).

### Preview
`StageCanvas.vue` rounds the polygon/triangle/star corners in the Konva config. Konva's
`RegularPolygon` and `Star` support a native `cornerRadius` prop in the bundled Konva
version — use it when available; if the shape is drawn as a closed `Line` (no native
`cornerRadius`), approximate with `tension`. Implementation confirms the Konva capability
at build time; preview is a close approximation, render is exact.

### Round-Trip
The parser reads `<n>.round_corners(radius=<cr_manim>)` and restores `cornerRadius` (px)
on the polygon/triangle/star object via inverse conversion.

## Security

No new expression input. `shadow.color` is a hex string passed through the existing `hex()`
sanitizer; numeric fields are clamped/formatted. `cornerRadius` is numeric.

## Coordinate / Parity Conventions

- Offsets/radii convert with the existing frame constants (`FRAME_WIDTH`/`FRAME_HEIGHT`),
  byte-identical multipliers in both generators.
- All emitted statements single-line (round-trip), per the project memory.

## Known Constraints / Risks

- `shadow.blur` is **preview-only**; the render shadow is a hard-edged shifted copy.
- `round_corners` preview on polygon/triangle/star is a Konva approximation; the render is
  exact (`VMobject.round_corners`).
- Shadow on a shape that is itself a `VGroup` (e.g. dashed) copies the group — works, but
  the shadow reproduces the dashed pattern (acceptable / expected).
- Glow is out of scope.
