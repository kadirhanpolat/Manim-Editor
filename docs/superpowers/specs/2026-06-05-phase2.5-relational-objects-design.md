# Phase 2.5 — Relational Objects (Brace + Angle) Design

**Date:** 2026-06-05
**Status:** Approved, ready for implementation planning
**Scope:** 2 new standalone object types — `brace`, `angle` — in a single spec.
**Base branch:** `feat/phase2.5-relational`, branched from `main` (carries Phase 1 effects +
all Phase 2 objects + `FRAME_WIDTH` coordinate unification).

## Goal

Add the two most-requested relational Manim mobjects for math/geometry videos — a
**Brace** (bracket spanning two points, with an optional label) and an **Angle**
(angle mark between two rays from a vertex, with a right-angle mode and optional
label). Both follow the existing constructor → styling → single-line round-trip
pattern and the `codegen.js` ↔ `manim.js` byte-identical parity convention.

## Key Architectural Decision: Independent Geometric Definition

Manim's `Brace`/`Angle` reference *other* mobjects. This editor's objects are
**self-contained** (built at object-relative coordinates, positioned by a generic
post-switch `move_to`). To preserve that model and avoid a dependency graph,
both new types are defined by **their own points** (object-relative px, centered on
`obj.x`/`obj.y`), exactly like `polygon_free` vertices:

- **Brace** — two points (`p1`, `p2`). Emitted via `BraceBetweenPoints`.
- **Angle** — three points (`vertex`, `point1`, `point2`). Two helper `Line`s are
  constructed inline and passed to `Angle` / `RightAngle`.

This keeps move/scale/rotate working through the standard transform, keeps each
emitted statement single-line (parseable), and needs no ordering/dependency logic.

## Non-Goals

- True relational references (`Brace(some_obj, RIGHT)` bound to another object's id),
  dependency tracking, auto-follow when a target moves — deferred (the hybrid option
  was rejected during brainstorming).
- Vector components (Arrow + dashed projections + labels) — deferred to a later phase.
- Keyframing the type-specific fields (points/radius/label). Standard keyframeable
  props (x, y, opacity, rotation, scale) work as today via the object center.
- Phase-1 effects (gradient/dash/rounded) on these objects — they are stroke marks;
  not added to `GRADIENT_TYPES`/`DASH_TYPES`.

## A) Object Types

Each new object carries the standard base fields created by `addObject`
(`id, type, name, x, y, width, height, rotation, fill, stroke, strokeWidth, opacity,
zOrder, visible, enterTime, duration, enterAnim, exitAnim, enterAnimDur,
exitAnimDur`) plus the type-specific fields below. `SHAPE_DEFAULTS`, `SHAPE_COLORS`,
and the `nameMap` in `store/project.js` gain an entry per type; the sidebar gains a
button per type.

Points are **object-relative px** (centered on the object's x/y), converted to Manim
units with the same scale as `polygon_free`:
`mx = px / sw * FRAME_WIDTH`, `my = -py / sh * FRAME_HEIGHT`.

### `brace`

- **Fields:** `p1: [x, y]`, `p2: [x, y]` (object-relative px), `label: ''`
  (optional LaTeX string), `braceDir: 'auto'` (bulge direction; `'auto'` =
  perpendicular to the p1→p2 line, Manim's default).
- **Defaults:** a horizontal brace — `p1 = [-80, 0]`, `p2 = [80, 0]`, `label = ''`.
- **Codegen:**
  - Unlabeled (single line):
    `<n> = BraceBetweenPoints([<x1>, <y1>, 0], [<x2>, <y2>, 0])`
  - Labeled (two lines):
    `<n>_brace = BraceBetweenPoints([<x1>, <y1>, 0], [<x2>, <y2>, 0])`
    `<n> = VGroup(<n>_brace, <n>_brace.get_tex(r"<safeLatex(label)>"))`
  - Then standard `set_color`/`set_stroke` on `<n>` and the generic post-switch
    `<n>.move_to([mp.x, mp.y, 0])`.
- **Konva preview:** a straight base line p1→p2 plus an approximate perpendicular
  bracket path (two arms curving to a center tip), drawn with `obj.stroke`; optional
  label text near the tip. Two draggable handles (p1, p2). Composite group with a
  listening hit region (per the composite-object selectability convention).

### `angle`

- **Fields:** `vertex: [x, y]`, `point1: [x, y]`, `point2: [x, y]`
  (object-relative px), `rightAngle: false` (square-corner mark mode), `radius: 0.6`
  (arc radius in Manim units), `label: ''` (optional LaTeX string).
- **Defaults:** a 90°-ish open angle — `vertex = [-40, 40]`, `point1 = [80, 40]`,
  `point2 = [-40, -60]`, `rightAngle = false`, `radius = 0.6`, `label = ''`.
- **Codegen (helper lines, each single-line):**
  ```
  <n>_l1 = Line([<vx>, <vy>, 0], [<ax>, <ay>, 0])
  <n>_l2 = Line([<vx>, <vy>, 0], [<bx>, <by>, 0])
  <n> = Angle(<n>_l1, <n>_l2, radius=<radius>)
  ```
  - When `rightAngle` is true, the third line is
    `<n> = RightAngle(<n>_l1, <n>_l2)` (no `radius` arg).
  - When `label` is non-empty, the `Angle`/`RightAngle` line is named `<n>_arc`
    instead of `<n>`, and a VGroup line follows (each single-line):
    `<n>_arc = Angle(<n>_l1, <n>_l2, radius=<radius>)`  (or `RightAngle(<n>_l1, <n>_l2)`)
    `<n> = VGroup(<n>_arc, <n>_arc.get_tex(r"<safeLatex(label)>"))`
  - Then standard `set_color`/`set_stroke` on `<n>` and generic `move_to`.
- **Konva preview:** two rays from `vertex` to `point1`/`point2`, plus an arc between
  them at `radius` (or a small square when `rightAngle`); optional label text at the
  arc midpoint. Three draggable handles (vertex, point1, point2). Composite group +
  listening hit region.

### Labels (both types)

- Optional LaTeX, sanitized via the existing `safeText`/`safeLatex` convention
  (escape/strip for safe Python string emission) and emitted as a raw string in
  `get_tex(r"...")`. Empty label ⇒ no VGroup, no label line — the object is emitted
  in its simplest single-line form (`brace`) or helper-lines form (`angle`).

## B) Codegen / Round-Trip Parity

- All emitted **statements are single-line** (per the
  `codegen-single-line-constructors-for-roundtrip` project memory). Labeled forms
  add one `_brace`/`_arc` helper line + one `VGroup` line — each single-line.
- **Parser (manim.js):**
  - `brace`: match `<n> = BraceBetweenPoints([x1,y1,0], [x2,y2,0])`. If a following
    `<n2> = VGroup(<n>, <n>.get_tex(r"..."))` line references it, attach the label and
    use the VGroup var as the object's name. Reconstruct `p1`/`p2` from the literal
    arrays.
  - `angle`: track `<n>_l1`/`<n>_l2` `Line(...)` definitions in a small lookup (like
    `graphVarMap` for area/riemann), then on the `Angle(...)`/`RightAngle(...)` line
    reconstruct `vertex`/`point1`/`point2` from the two referenced lines' endpoints.
    Capture `radius` and `rightAngle` (constructor name). Attach optional label from a
    following `VGroup` + `get_tex` line.
- `codegen.js` and `manim.js` share no import; the new `case` arms, the helper
  emission, and any `safeLatex`/label helpers are kept **byte-identical** by
  convention, guarded by `manim-export.test.js` invariants.

## Security

- `label` is sanitized to a safe Python raw-string entry (escape `"`/backslashes per
  the existing `safeText` mechanism); it is passed to Manim `get_tex` as display
  LaTeX, no expression evaluation. No new math-expression input is introduced.

## Coordinate / Parity Conventions

- Points convert with the `polygon_free` scale (`FRAME_WIDTH`/`FRAME_HEIGHT`); the
  generic post-switch `move_to` positions the object/group.
- Keep the multipliers byte-identical between `codegen.js` and `manim.js`.

## Known Constraints / Risks

- Brace bulge shape and Angle arc/label placement are **preview-only approximations**
  in Konva (Manim renders the true brace glyph / angle arc). Convention validated by
  manual render comparison, not pixel tests.
- Labeled objects emit a `VGroup`; the canvas preview draws a single composite (like
  `matrix`/dashed-fill) — selection/transform act on the whole group.
- `angle`'s helper-`Line` round-trip depends on the two `Line` vars being emitted
  immediately before the `Angle` line and matching the `<n>_l1`/`<n>_l2` naming; the
  parser keys off that convention.
